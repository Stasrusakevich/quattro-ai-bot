# Quattro Assistant

Рабочий Telegram-бот команды Quattro Space. Новое ядро подготовлено 20.11.2026
для размещения программистами на существующем VPS ERP.

## Реализованное ядро

- Обычное сообщение в личном чате сохраняется как заметка и доставляется Стасу.
- `/task текст` и сообщения, начинающиеся с «Задача», «Стасу», «Для Стаса»,
  сохраняются как задачи. Меню содержит «Заметка», «Задача Стасу» и «GPT».
- Фото, документы, голосовые, аудио и видео сохраняются с Telegram file_id
  и отправляются владельцу по сохранённому file_id. Подпись хранится вместе с записью. Для голосовых
  сохраняется исходное сообщение. Автоматическое распознавание речи требует
  отдельного обработчика.
- `/gpt вопрос` вызывает OpenAI Responses API. Кнопка «GPT» включает режим
  вопросов до выбора другой кнопки, `/cancel`, `/start` или перезапуска.
- Вызов GPT выполняется фоном с общим таймаутом 50 секунд. Одновременно
  обрабатываются два запроса, по одному на сотрудника. При занятости вопрос
  сохраняется, а автор получает просьбу повторить его позже. Другие входящие
  продолжают сохраняться во время ожидания ответа GPT.
- Сохранение входящего и очередь уведомления создаются одной транзакцией SQLite.
  Повтор входящего сохраняет одну запись. Фоновая доставка работает каждые 15 секунд.
- Сотрудники и группы перечисляются в конфигурации по числовым Telegram ID.
  Общий список входящих и технические статусы доступны владельцу в личном чате.
- В группах бот реагирует на команды. Приватность включается через BotFather
  при подготовке владельцем бота. Текст групповой переписки, упоминания и обычные
  ответы боту остаются за пределами обработки команд.

## Запуск

Требуется Python 3.12. Создайте виртуальное окружение и установите зависимости.

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Возьмите имена настроек из `.env.example`. Обязательны `TELEGRAM_BOT_TOKEN` и
`ADMIN_USER_ID`. Для сотрудников задайте `ALLOWED_USER_IDS`, для рабочих групп —
`ALLOWED_CHAT_IDS`. При пустых списках личный доступ имеет владелец. Числовые ID
и ключи рабочей среды передаются администратором по каналу команды.

`DATA_DIR` указывает на постоянный каталог вне checkout выпуска. В нём создаются
`assistant.sqlite3`, файлы SQLite WAL и lock-файл единственного экземпляра.
Для локальной проверки можно задать абсолютный путь к отдельным тестовым данным.

`OPENAI_API_KEY` включает запросы GPT. `OPENAI_MODEL` задаёт согласованную модель,
по умолчанию `gpt-5-mini`. При отсутствии ключа приём заметок и задач работает,
а явный запрос GPT получает понятное сообщение о недоступности подключения.

```sh
.venv/bin/python -B bot.py
```

Для выбранного токена необходим один получатель обновлений. Перед первым
размещением сверяется существующая инфраструктура. Работающий webhook требует
согласованного переключения на long polling. Получение оставшихся обновлений
сохраняется при старте. Права существующих сервисов и схема перехода описаны
в инструкции VPS.

## Команды

| Команда | Действие |
| --- | --- |
| `/start`, `/help` | Инструкция и меню, возврат в режим заметок |
| `/note_add текст`, `/note текст` | Сохранить заметку и уведомить Стаса |
| `/task текст` | Сохранить задачу и уведомить Стаса |
| `/gpt вопрос`, `/ask вопрос` | Ответ GPT |
| `/cancel` | Вернуться в режим заметок |
| `/inbox` | Последние десять заметок и задач для владельца |
| `/notes`, `/tasks` | Последние десять записей выбранного типа для владельца |
| `/status` | Настройка GPT и состояния уведомлений для владельца |
| `/retry_notifications` | Повтор явных ошибок доставки после устранения причины |

Состояние `sent` означает успешный ответ Telegram с ID сообщения. `pending`
ожидает отправки или истечения `retry_after`. `failed` требует исправления причины
и команды владельца. `uncertain` требует ручной сверки доставки, поскольку запрос
мог выполниться до потери ответа. Команда повторов обрабатывает `failed`.

Вложения остаются в Telegram, в SQLite сохраняются file_id и происхождение.
Доставка использует сохранённый file_id и сохраняет работоспособность после
удаления исходного сообщения. Текстовая запись остаётся во входящих.

## Статус расширений

Расписания 19:00, работа с ERP, Битрикс24 и Google-таблицами, постановка задач
реализаторам, табель план-факт, РОП и финансовый контроль описаны в документах
как требования к следующим модулям. В этом ядре выполняются приём входящих,
доставка Стасу и ответы GPT. Серверные адаптеры и рабочие расписания подключаются
программистами по согласованным контрактам. Сейчас вечерние проверки выполняются
существующей автоматизацией Codex на рабочем компьютере.

В GPT загружается проверяемая справка `knowledge/assistant.md`. Остальные
исторические материалы `knowledge/` сохраняются для редакторского пересмотра
перед включением в новую базу знаний. Системные правила находятся в
`prompts/system_prompt.txt`.

## Проверки

```sh
.venv/bin/python -B -m unittest discover -s tests -v
.venv/bin/python -B -m unittest discover -s deploy -p 'test_*.py' -v
```

Проверки ядра и восстановления доставки используют временные базы и подменяют Telegram/OpenAI. Они покрывают
маршрутизацию, доступ, запись, повторные и конкурирующие операции, частичную
доставку, ошибки провайдеров и изоляцию GPT-контекста. Живой ответ OpenAI,
рабочая доставка и Linux/systemd проверяются на VPS при приёмке.
