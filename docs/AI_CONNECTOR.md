# AI-коннектор Quattro Assistant

Реализация от 25.11.2026. Один выбранный провайдер на процесс: DeepSeek,
OpenAI GPT или Anthropic Claude. Коннектор находится в `services/ai.py`.
Production в рамках этой задачи не обновляется; AI остаётся выключенным.

## Настройки

Настройки читаются при запуске из окружения процесса и локального `.env`.
Окружение процесса имеет приоритет: `load_dotenv` не перезаписывает его.
На сервере действующий systemd unit читает `/etc/quattro-assistant.env`.
Для будущего переключения потребуется перезапуск процесса; горячей смены нет.
Рабочий env не хранится в Git.

| Переменная | Назначение |
| --- | --- |
| `AI_ENABLED` | Только `true` (без учёта регистра и крайних пробелов) включает AI. Отсутствие, `false`, пустая строка и ошибочные значения выключают его |
| `AI_PROVIDER` | `deepseek` по умолчанию; также `openai`, `anthropic` |
| `AI_MODEL` | API ID модели выбранного провайдера. Пустое значение использует его значение по умолчанию |
| `DEEPSEEK_API_KEY` | Только для DeepSeek |
| `OPENAI_API_KEY` | Только для OpenAI |
| `ANTHROPIC_API_KEY` | Только для Anthropic |
| `OPENAI_MODEL` | Совместимость с прежней настройкой: только для `openai`, если `AI_MODEL` пуст. По умолчанию `gpt-5-mini` |

Ключи сами по себе AI не включают. При старом env без `AI_ENABLED` запросы
к провайдерам выключены, даже если в нём остался `OPENAI_API_KEY`.
Неизвестный провайдер, отсутствующий ключ или ошибка API делают недоступным
только AI-запрос; приём заметок, задач и уведомления продолжают работать.

| Провайдер | Модель при пустом `AI_MODEL` | API |
| --- | --- | --- |
| `deepseek` | `deepseek-flash` | `https://api.deepseek.com/chat/completions` |
| `openai` | `OPENAI_MODEL`, иначе `gpt-5-mini` | `https://api.openai.com/v1/responses` |
| `anthropic` | `claude-sonnet-4-6` | `https://api.anthropic.com/v1/messages` |

API ID DeepSeek проверен 25.11.2026 по [официальному руководству](https://api-docs.deepseek.com/):
`deepseek-flash` обслуживается DeepSeek-V4.1-Flash-1017. Это обновляемое имя
модели у провайдера; коннектор не закрепляет её веса. Старые имена
`deepseek-v4-flash` и `deepseek-v4-flash-vision-exp` уже обозначают выведенные
версии и временно перенаправляются провайдером на Flash. Их в настройках по
умолчанию не используем.

Другие официальные спецификации:
[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/),
[OpenAI Responses](https://developers.openai.com/api/reference/resources/responses/methods/create),
[Anthropic Messages](https://platform.claude.com/docs/en/api/messages/create),
[версии Anthropic API](https://platform.claude.com/docs/en/api/versioning),
[ID моделей Claude](https://platform.claude.com/docs/en/about-claude/models/model-ids-and-versions).
Доступность конкретной модели и оплаченного API определяется учётной записью
провайдера. Пользовательские API ID передаются как есть, без списка разрешённых
моделей в коде. Выбранная модель должна поддерживать соответствующий текстовый API.

## Примеры конфигурации

Безопасное исходное состояние (также в `.env.example`):

```dotenv
AI_ENABLED=false
AI_PROVIDER=deepseek
AI_MODEL=deepseek-flash
DEEPSEEK_API_KEY=
OPENAI_API_KEY=
ANTHROPIC_API_KEY=
```

После отдельного решения включить AI задаются `AI_ENABLED=true` и ключ только
выбранного провайдера. При смене провайдера меняйте также `AI_MODEL` либо
очищайте его для использования соответствующей модели по умолчанию:

```dotenv
# OpenAI: прежний Responses API и прежняя модель
AI_PROVIDER=openai
AI_MODEL=gpt-5-mini
```

```dotenv
# Anthropic: нативный Messages API
AI_PROVIDER=anthropic
AI_MODEL=claude-sonnet-4-6
```

Примеры не включают production и не требуют менять существующие секреты.
`/status` в личном чате владельца показывает выключенный режим либо выбранного
провайдера, модель и наличие нужного ключа. Команда не делает внешнего запроса,
не подтверждает валидность ключа и не раскрывает его.

## Сохранённое поведение

- Кнопка «GPT», команды `/gpt` и `/ask` сохранены для совместимости; они обращаются
  к выбранному провайдеру. Настройки не доступны через Telegram.
- Все адаптеры получают одинаковый текст `prompts/system_prompt.txt` и справку
  `knowledge/assistant.md`, ту же историю и текущий вопрос ровно один раз.
  OpenAI получает инструкции отдельно, DeepSeek — в system-сообщении,
  Anthropic — в поле `system`.
- SQLite, хранение ответов, повтор Telegram-обновлений и права доступа не меняются.
  В личном чате передаются последние пять успешных пар вопрос/ответ того же
  пользователя и чата. В группах история не передаётся. Неуспешные запросы
  не включаются в историю. После ручной смены провайдера существующая допустимая
  история сохраняется и будет передана вновь выбранному провайдеру.
- Сохраняются два одновременных запроса, максимум один на сотрудника, фоновое
  выполнение и внешний таймаут бота 50 секунд. Коннектор ограничивает весь
  вызов 45 секундами; HTTP-операции также имеют таймаут 45 секунд.
- Лимит ответа — 2000 токенов. Для DeepSeek явно выключен thinking, чтобы
  сохранить короткий текстовый ответ в существующем бюджете и таймауте.
  Параметры расширенного reasoning, инструменты, мультимодальный ввод и streaming
  в этой версии не добавляются.
- Автоматических повторов и fallback нет. При 401, 429, 5xx, сетевой ошибке,
  таймауте, пустом или незавершённом ответе бот сохраняет вопрос как неуспешный
  и сообщает о недоступности. Повтор — новым сообщением пользователя.
- Endpoints закреплены за адаптерами; `OPENAI_BASE_URL` их не меняет. OpenAI
  сохраняет прежний `store=False`. Для Anthropic используется HTTPX напрямую
  с `anthropic-version: 2026-10-21`, без перенаправлений и повторов.
- В технический журнал попадает тип ошибки, а не её тело, ключи или полный
  корпоративный контекст. Исключения провайдера заменяются безопасной ошибкой.
  Содержимое вопроса/ответа продолжает храниться в SQLite по прежним правилам.
  Политики хранения данных у внешних провайдеров определяются их условиями.

## Локальная проверка

```sh
.venv/bin/python -B -m unittest discover -s tests -v
.venv/bin/python -B -m unittest discover -s deploy -p 'test_*.py' -v
.venv/bin/python -m pip check
git diff --check
```

`tests/test_ai.py` проверяет реальную сериализацию OpenAI SDK и HTTP-запросы
Anthropic через `httpx.MockTransport`, без внешних AI-вызовов. Покрыты ключи,
выбор провайдера/модели из env, выключенный режим, инструкции, история,
пустые/незавершённые ответы, ошибки API, сеть, таймауты, отмена и отсутствие
повторов. Проверки маршрутизации дополнены сценариями выключенного AI с
заданными ключами, запрета доступа и статуса для владельца.

Живые AI API и Telegram не вызываются: нужны отдельно согласованные тестовые
ключи и токен. Полноценный ответ и доступность модели на платном аккаунте эти
тесты не подтверждают. VPS, production env, CI/CD и main не изменяются.
